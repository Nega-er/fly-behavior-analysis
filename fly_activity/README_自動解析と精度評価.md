# 任意動画・個体数選択・自動前進後退・人手評価

Windowsでは `ハエ解析アプリ.bat`、Macでは `ハエ解析アプリ.command` をダブルクリックすると、新しい解析画面が開きます。
従来の動画専用ランチャーや頭側確認ツールは旧解析の再現用です。
新しい画面では、頭側の事前クリックを要求しません。

## Windowsでの起動

Python 3.10以上（Tcl/Tkを含む）をインストールし、`ハエ解析アプリ.bat` をダブルクリックします。
Pythonランチャーの `py -3`、またはPATHに登録された `python` を利用します。
初回はプロジェクト直下に専用環境 `.venv` を作成し、必要なライブラリを自動インストールします。
初回のインストールにはインターネット接続が必要です。2回目以降は同じ環境を再利用します。
エラーが発生した場合は画面を開いたまま原因を表示します。修正後に再実行してください。
「結果フォルダを開く」はWindowsのエクスプローラーで開きます。

**人手評価のたびに累積学習する機能を追加しました。** 初期モデルと過去の教師データを
保持したまま、次回の解析で最新版を使用します。評価画面の学習設定は初期値ONです。

## 操作

1. **動画ファイル → 選択**：MP4・AVI・MOV・MKV等、OpenCVで読み取れる動画を選択します。
2. **個体数**：`auto` で自動推定、`7` などの正の整数で手動指定します。
   「自動推定を確認」で推定値、検出数の範囲、最頻値の割合を確認できます。
3. 必要なら「解析領域を選ぶ」で容器内をドラッグし、Enterで確定します。
   全画面も使用可能です。別動画を選ぶと領域と背景画像指定はリセットされます。
4. 明るいハエはbright、暗いハエはdark、両方向の差分が必要ならbothを選びます。
   輝度差、最小・最大面積、速度上限を映像の拡大率に合わせて調整します。
   背景画像は任意指定でき、未指定の場合はその動画から明暗に応じた時間パーセンタイル背景を作ります。
5. **自動解析を実行**：出力先に動画名・日時の新しい結果フォルダを作ります。
6. **人間による精度評価**：自動判定を表示しない短い原動画を見て、行動を選びます。
   過去の自動結果も、結果フォルダを選んで評価できます。
   白い円が対象個体です。追跡が連続する区間を切り抜き、移動中も対象が画面内に入るように表示します。
   評価時刻の座標が欠ける場合は対象を確認できない旨を表示し、「判断不能 U」で次へ進みます。
   この場合は前進・後退・停止・横方向の入力を無効にします。個体を見分けられない場合も「判断不能」を選んでください。

## GUIで結果をまとめて表示

解析終了後は自動で「解析結果」タブへ切り替わります。
「過去の結果を表示」または結果タブの「結果を読込」で、既存の結果フォルダも読み込めます。

- **概要**：動画・個体数・観測時間・総移動距離・有効観測率・前進後退等の時間と割合。
- **グラフ**：移動距離・移動停止と前進後退の図。幅に合わせる表示、拡大、縦横スクロール。
  「単位時間あたりの移動量」には時間窓ごとの群全体・個体別・有効時間補正の移動量を表示します。
- **個体別**：表示番号ごとの距離、移動・前進・後退・停止・不明時間、有効観測率、追跡区間数。
- **追跡品質**：欠測、確認対象フレーム、推定個体数のばらつき、不明理由別の時間。
- **精度評価**：人手評価の件数、一致率・判定率、クラス別の適合率/再現率/F1、混同行列。

「動画を表示」で確認動画をGUI内で再生できます。再生位置と速度を変更できます。
方向確認動画の矢印は緑＝頭向き、水色＝変位です。
人手評価がない場合、精度は「未評価」、個々の算出不能な値は「—」になります。
人手評価画面を終了すると、現在表示している結果の集計を自動で再読込します。
別ウィンドウで評価した場合も「再読込」で更新できます。
結果画面は保存済み結果を読むだけで、座標・自動ラベル・人手ラベルを書き換えません。
「最新モデルで再解析」で、同じ動画・解析条件から別の結果フォルダを作成できます。
旧結果に新しい移動量グラフがない場合も、time_bins.csvからGUI内で作図できます。
旧フォルダへファイルを書き足す処理は行いません。

## 0〜30秒・30〜60秒・60秒以降の統計検定

解析終了時に自動集計し、概要と「3区間の統計検定」タブに表示します。
各個体について区間の測定距離を有効観測秒数で割った平均移動距離（px/sまたはmm/s）を比較します。
停止は観測時間に含めます。60秒以降の区間長が異なっても比較でき、欠測は移動距離0とは扱いません。
フレーム間隔が30秒・60秒の境界をまたぐ場合は、距離と有効秒数を重なり時間に比例して分けます。

同じ表示IDを対応させ、3区間すべてに有効観測がある個体だけを検定に使用します。
全体は個体内で区間を入れ替える平均差の置換検定です。有意水準は5%です。
区間同士も対応のある両側置換検定を行い、3比較のp値をHolm法で補正します。
全体検定は最大19,999回（乱数固定）、区間同士は最大65,536回以上で計算します。
可能な入れ替えの総数が回数以内なら全列挙し、それ以外は乱数近似です。
個体を独立な観測単位とし、帰無仮説の下で区間ラベルが交換可能であることを仮定します。
個体数・除外個体・各区間の有効観測率・平均・標準偏差・補正p値を併記します。
60秒以降のデータがない場合、または3区間で観測できた個体が2個体未満の場合は検定不可と表示します。

同一容器内の個体は独立でない可能性があり、追跡区間をまたぐID一致も保証されません。
これは同じ動画内の探索的比較です。複数容器・試行を使った母集団への推論とは区別してください。
「有意差を検出せず」は差がないことの証明ではありません。

新しい解析では `period_statistics.json` と `period_individuals.csv` を保存します。
過去の結果も、読み込み時にactivity.csvから表示用の集計を行います。旧フォルダには書き込みません。
計算法の参考：[SciPyの対応のある置換検定](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.permutation_test.html)。

## 白っぽい本体と影を分ける検出

「本体検出」の初期値autoでは、十分に明るい個体候補がある場合、白い本体の中心部分を
抽出してから面積制限を適用します。背景差分で暗い影や翅を含めた面積が大きくなって
本体が除外され、影だけが残る問題への対策です。暗めの動画では従来の背景差分を維持します。

- `auto`：十分明るい本体がある場合だけ本体中心の抽出へ切り替えます。
- `body_core`：本体中心の抽出を常に使用します。
- `background_diff`：従来の背景差分のみ。旧処理の比較にも使えます。
- 「本体輝度下限」0は自動設定、正の値は手動指定です。白いハエでは例えば180で暗い影を除きます。
  暗いハエdarkの場合は反転輝度（255−画素輝度）への下限として働きます。

自動の場合、面積の上限を適用する前の候補から上位のピーク輝度を選び、初期値では
基準輝度が200以上なら、その70%を本体の画素の下限に使います。
`body_core_reference_min` と `body_core_fraction` で調整できます。
個体数推定と本追跡で同じ検出処理を使います。実際に適用した下限はquality.csvの
`body_core_threshold`、切替状態は `body_core_applied` に記録します。

今回の3-1.aviでは、旧処理が落としていた白い本体を保持し、暗い影を除外することを
複数のフレームで確認しています。再解析例は `outputs/3-1_body_core` です。
接触した個体や反射と重なる個体は引き続き不確実な場合があります。
頭尾の自動モデルは元の撮影条件から学習したもので、この動画の頭尾精度は別途人手評価が必要です。

## 単位時間あたりの移動量の変化

「移動量の集計幅（秒）」の初期値は1秒です。例えば0.5、2、5へ変更できます。
新しい `movement_rate.png` と `movement_rate.csv` を保存し、GUIにも表示します。

1. 群全体：各時間窓の測定距離の合計 ÷ その窓の経過時間（px/sまたはmm/s）。
2. 個体別：各個体の測定距離 ÷ その個体の有効観測秒。
   太い黒線は、群の測定距離合計 ÷ 有効個体秒の合計で求めた平均です。
3. 有効観測率：有効個体秒 ÷（指定個体数 × 窓の経過時間）。

最後の窓が短い場合は実際の時間幅で割ります。有効観測が0の窓は空欄・グラフの欠落にし、
停止や移動量0とは扱いません。観測時間による補正だけで、接触などに偏った欠測の影響が
なくなるわけではありません。観測率も一緒に確認してください。

集団の行動時間は**個体秒**で表示します。例えば2個体が1秒ずつ前進した場合は2個体秒です。
個体別の表は各個体の秒数です。前進後退用と従来の移動停止用には別の閾値があるため、
「移動時間」と「前進＋後退＋横方向等の時間」が一致するとは限りません。

既存結果を指定して起動する場合：

```sh
python fly_activity/app.py --results /path/to/results
```

画面の動作環境はPython 3.10以上、Tkinter、requirements.txtのライブラリです。
この環境では既存AMADEUSのPythonを利用します。別環境ではTkinterが利用可能なPythonを
用意し、`python -m pip install -r fly_activity/requirements.txt` を実行してください。

## 個体数の自動推定

動画全体から最大31時点を採り、背景差分で検出した面積範囲内の成分数の最頻値を使います。
検出数が同頻度なら大きい方を採用します。これは画像上の個体候補数の推定です。
接触による結合、反射による分裂、静止個体の背景への取り込みでは誤ります。
`population_estimate.json` と `population_samples.csv` に根拠を保存します。
個体数を固定指定しても検出点を強制的に分割してその数に合わせることはありません。
画面で推定値を確認し、必要なら実際の数を手動で指定してください。

## 自動の頭尾・前進後退判定

旧 `head_model.json` は94サンプルの初期外見モデルです。累積学習では、元の頭側入力を
現在の検出条件で抽出した95サンプルの `learning/seed_model.json` と、人手評価の追加教師を
使用します。輪郭と背景との輝度差を体軸に沿って正規化し、両端の外見の差を
正則化ロジスティック回帰で判別します。移動方向を頭向きと仮定する処理は使いません。
体軸の符号が反転した場合には両端の予測確率も反転する構成です。

確信度0.6以上の外見判定から頭向きを決め、弱いフレームは連続した信頼できる体軸から
向きを引き継ぎます。欠測・不鮮明な体軸などではリセットし、後続の外見判定で再開します。
方向の分類方法は従来と同じ体軸方向への移動の投影です。
`automatic_head_confidence` はモデルの確信度スコアで、校正された正解確率ではありません。
このモデルは一つの撮影条件の小規模な学習データによる試作です。
別の種、視点、解像度、照明では精度が変わるため、人手評価を行ってください。

出力の例：

| ファイル | 内容 |
|---|---|
| `tracks.csv` | 座標・体軸・外見モデルの頭側確率・画像更新間隔 |
| `activity.csv` | 移動停止、前進後退、符号付き速度、確信度、判定理由 |
| `direction_report.png` | 自動の前進・後退・横方向等・停止・不明の時系列 |
| `direction_preview.mp4` | 頭向きと変位を重ねた自動結果の確認動画 |
| `direction_summary.csv` | 方向別の時間と測定距離 |
| `population_estimate.json` | 推定個体数とそのばらつき |
| `metadata.json` | 元動画、個体数の選択方法、モデル・動画のハッシュ、学習元と同じ動画か |

従来の移動距離・追跡品質・時間集計の出力も保存します。初期の距離単位はpxです。
遮蔽や接触後の個体IDは保証しません。個体別と群全体の指標はその制約を考慮して使用します。

## 人間による精度評価

評価元の自動結果は固定したまま、人手の参照ラベルを別ファイルに保存します。
初期値では、このラベルを累積学習にも使用します。以前の自動結果へ直接書き戻すことはありません。
独立した精度評価に使う場合は「入力ごとに累積学習する」をOFFにしてください。

- 白い円の対象個体について、中央時刻の動作を判断します。短い原動画を繰り返し表示します。
- 前進F、後退B、停止S、横方向等L、判断不能Uをボタンまたはキーで入力します。
- 頭尾や個体同定が分からないものは判断不能にしてください。
- 各入力で保存し、画面を閉じても同じ結果フォルダの評価を再開できます。
- 評価試料は自動ラベルに依存せず、フレームと個体表示番号の組から乱数シード付きで選びます。
- 同じ動画をモデル学習に使っていた場合、その入力フレームの前後0.4秒を評価試料から除きます。
  それでも同じ動画内の評価は、別動画への汎化精度とは区別します。
- 評価試料がなくなる場合は、別動画を使って評価してください。

| ファイル | 内容 |
|---|---|
| `human_evaluation.csv` | 評価試料・固定した自動予測・人手のラベル |
| `evaluation_sampling.json` | 抽出方法、シード、学習動画との関係、自動結果のハッシュ |
| `evaluation_metrics.json` | 全体一致率・判定率・クラス別の適合率/再現率/F1 |
| `evaluation_confusion.csv` | 人手ラベル×自動ラベルの混同行列 |
| `evaluation_report.md` | 人手評価の要約 |

主な一致率は、人が判断できた試料のうち自動と一致した割合です。
自動unknownは誤りに含め、unknownを除外した一致率と判定率も別に出します。
人の判断不能は分母から除き、その件数を併記します。
したがって、この評価だけで検出漏れ・個体IDの精度を評価したことにはなりません。
時間的に近い試料は相関があるので、試料数を独立した実験反復数とは扱いません。
人の評価がない段階では一致率はnullであり、精度を作って表示することはありません。

## コマンドでの実行

任意動画・個体数自動・自動頭尾判定（設定ファイルなしの場合、背景と領域は動画ごとに用意）：

```sh
python fly_activity/analyze_flies.py --video /path/to/video.mp4 --flies auto --out /path/to/new_results
```

個体数を指定：

```sh
python fly_activity/analyze_flies.py --video /path/to/video.mp4 --flies 7 --out /path/to/new_results
```

暗いハエなどはGUIまたは動画専用のJSON設定を使います。既存example_config.jsonは
元の1080×1080動画の背景と円形領域を指定しているため、別動画にそのまま流用しないでください。
独自の頭尾モデルは `--head-model /path/to/model.json` で指定できます。
モデルの学習コードはautomatic_head.pyにあります。評価ラベルを学習に使う場合は、
別のテスト動画・ラベルを確保し、学習と評価を分離してください。

人手評価：

```sh
python fly_activity/evaluate.py --results /path/to/automatic_results --samples 80 --seed 0
```

学習せず、評価専用にする場合は `--no-learn` を追加します。

## 累積学習の動作

1. 人手の行動を選ぶたびにラベルを保存します。
2. 有効な座標・体軸・画像特徴がある例を、SQLiteの累積教師データへ登録します。
3. 元の教師データと全ての追加教師を使って頭尾モデルを再学習し、行動の補正モデルも更新します。
4. 新しいモデルをバージョン付きで保存し、最新版への参照を切り替えます。
5. 次の自動解析で最新版を読み込みます。実行中の解析が途中で別モデルに切り替わることはありません。

**前進・後退の教師**では、体軸と移動の対応が十分明瞭な場合（方向比率の絶対値0.6以上）、
人の行動ラベルから頭側の教師を作り、外見モデルに追加します。全ての移動を前進だと
仮定する処理ではなく、人が前進か後退かを判定した例だけを使用します。
**停止・横方向等を含む教師**は、外見と体軸に対する移動から作った特徴を蓄積し、近い事例への
行動補正に使います。類似度・ラベルの一致が十分高い場合だけ補正し、離れた事例には従来判定を使います。

判断不能、追跡欠測、不明瞭な体軸、前進後退を教えるには移動が小さすぎる例は、
ラベルを保存しますが教師データには使いません。評価画面にその状態を表示します。
同じ例を同じラベルで再登録しても重複学習しません。ラベルを訂正すると既存教師を更新し、
訂正前の履歴も保存します。画像座標や移動距離自体を学習で書き換えることはありません。

| 保存場所・列 | 内容 |
|---|---|
| `learning/examples.sqlite3` | 累積教師データ、ラベル訂正履歴、モデル履歴 |
| `learning/seed_model.json` | 初期の頭側教師データとモデル |
| `learning/models/model_XXXXXX.json` | 各バージョンの頭尾モデルと行動補正データ |
| `learning/current.json` | 最新版への参照と学習件数 |
| 各結果の `appearance_features.npz` | 画像特徴のキャッシュ。次の人手評価時に再利用 |
| `human_evaluation.csv` の `learning_status`, `learned_model_version` | 入力を学習した状態とモデル版 |
| `learning_status.json` | この結果の教師入力・取込み状態 |
| `metadata.json` の `learning_version` | 実際の解析に使用したモデル版 |
| `activity.csv` の `baseline_locomotion_direction` | 行動補正前の判定 |
| `activity.csv` の `learning_confidence`, `direction_reason` | 補正の確信度と適用理由 |

行動補正と頭尾モデルは別なので、補正後の前進後退と、頭向きから計算した符号付き速度が
一致しない場合があります。`cumulative_human_correction` が補正を適用した区間です。
動画の頭矢印は外見モデルの推定を表示します。確信度は校正された正解確率ではありません。

今回、既存の評価174件を取り込み、そのうち行動に143件、頭尾の追加教師に18件を使用しました。
取込み後の初期最新版はv174です。過去の評価ファイルの人手ラベルや自動予測は変更していません。

評価表は**評価元モデルの固定予測**との比較です。そのラベルを使った更新後モデルの精度を
同じ表で主張することはできません。新しいモデルの精度を見る場合は、新しい解析結果から
学習に使っていない試料を取り、評価専用モードにしてください。モデルは動画のハッシュと
学習フレームを記録し、新規評価では学習フレームの前後0.4秒を除きます。
同じ動画の未使用区間による評価と、別動画への汎化評価も区別します。

旧結果の評価を追加取込みする場合（同じ例は重複登録されません）：

```sh
python fly_activity/cumulative_learning.py --import-results /path/to/results1 /path/to/results2
```

特定のモデル版を固定して解析する場合は、`--head-model learning/models/model_000174.json` のように指定します。

旧方式の `--head-anchors` は互換性のため残していますが、その結果は自動判定の精度評価に使えません。
今回の自動実行例は `results_automatic` です。個体数は7と自動推定し、手動の頭側入力を
解析時に使わず438フレームを処理しています。人手評価はこれから入力してください。


### 停止個体のID保持

欠測時もIDを予約し、位置と外見から同じIDへ再対応付けします。入力画面で再識別の
保持時間・静止ID保持時間・最大探索距離を設定できます。遠い候補は複数画像で確認し、
曖昧な区間の距離は加算しません。自動個体数は繰り返し観測した上側の成分数を参照します。
結果の「ID再対応付け」で行を選ぶと、見失う前から追跡動画を開けます。
この一覧と追跡品質の処理件数は、ID精度の実測値ではありません。
詳細と実動画比較はREADME.mdの「停止個体のID保持と個体数の改善」を参照してください。


## 解析の進捗表示

画面下部の積層バーは、動画準備・個体追跡・行動解析・集計と図の保存・確認動画・結果表示を色別に表示します。
完了した工程の色が残り、現在の工程は処理したフレーム数や個体数に応じて進みます。
全体の割合は工程ごとの重みを使った目安で、残り時間の予測ではありません。
結果タブでも表示され、結果の読込みと表示が終わってから100%になります。
エラー時は完了扱いにせず、中断時点の進捗を残します。


## 学習用の優先抽出とUnknown入力

入力画面の「人手入力の場面選択」で、学習用（優先抽出）と評価用（ランダム）を選択できます。
初期設定の学習用では、自動Unknown・後退候補・頭尾の低確信度・通常のランダム抽出に各約25%を割り当てます。
該当候補が足りない枠はランダムな候補で補い、同じ個体の候補は0.6秒以上離します。
対象座標と有効区間がある場面に絞り、既知の学習時刻の前後0.4秒を除きます。候補が足りない場合は指定件数より少なくなります。
自動の正解は画面に表示しません。

人が判別できない場面は「Unknown U」で保存できます。Unknownは行動や頭尾の正解教師に使わず、精度の分母から除外します。
過去の「判断不能（unscorable）」も同じ扱いで読み込みます。自動Unknownに対して人が前進・後退などを選んだ場合は、従来の条件を満たす例を教師に使います。

学習用の入力は `human_learning.csv`、抽出根拠は `learning_sampling.json`、入力集計は `learning_metrics.json` と `learning_report.md` に保存します。
従来の `human_evaluation.csv` と評価集計は別に保持し、再開時はそれぞれの未入力分を表示します。
優先抽出の一致率は動画全体の精度を表しません。評価用を選ぶと、アプリは学習OFFでランダムな人手評価を起動します。
累積教師とモデル履歴の保存先は引き続き `tuji/fly_activity/learning` です。
