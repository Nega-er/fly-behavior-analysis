| `summary_group.json` | 容器全体の測定距離と有効個体秒・観測率 |
| `bouts.csv` | 移動・停止の開始終了、持続時間、距離、打切りフラグ |

| `background.png`, `first_frame_overlay.jpg` | 背景と最初のフレームの検出確認 |

CSVはUTF-8 BOM付きで、Excelでも開けます。座標は画像左上が原点、xは右方向、yは下方向。
`activity.csv` の各行の距離・速度・状態は、そのフレームで終了する時間区間の値です。
最初のフレームには時間幅がないため状態はunknownです。

**スロット番号は、接触や欠測後まで保証された生物学的な個体IDではありません。**
見失ってもIDを予約し、追跡中の個体を先に対応付けてから、位置・面積・形状・輝度で再識別します。
再対応付け後も距離の欠測を埋めないため新しいsegmentになります。`summary_by_slot.csv` は
同じ予約IDに対応付けた区間の合計です。接触後などの区間をまたぐ結論には動画確認が必要です。
区間が一つでも、無標識個体のID精度を保証するものではありません。

## 処理方法

1. 既存の背景画像を読み、ぼかした画像との差分で検出します。
   初期設定は明るいハエの正方向差分です。暗いハエでは `foreground_polarity` を
   `dark`、両方向の差分が必要なら `both` に変更します。
2. 円形ROI内の成分を面積で選びます。7個体になるよう強制分割はしません。
3. 予測位置と外見を用いた全体割当（Hungarian法）で対応付けます。追跡継続を優先し、
   未観測IDの最後の位置は予約します。欠測IDを無関係な検出に番号順で割り当てません。
4. 近接した検出、候補間の差が小さい割当、速度上限を超える割当を採用しません。
5. 見失いや曖昧な対応を挟んだ距離は加算せず、再検出時に新しい区間にします。

背景指定がなければ、明るい個体は標本の10パーセンタイル、暗い個体は90パーセンタイル、
両方向検出は中央値から背景を作ります。長い停止で本体が背景に入る問題を軽減します。
静止IDの既知位置で差分が消えた場合は、局所コントラストと明るい／暗い本体の画像証拠で
補助検出します。画像証拠がない場合は欠測のままで、停止や座標を捏造しません。
全標本で同じ場所にいる未検出個体はこの方式だけでは初期検出できない場合があります。
その場合は同じ撮影条件の無個体背景画像を指定してください。

## 距離・移動停止の定義

- 距離は中心座標の連続区間のユークリッド距離を加算します。
- `raw_distance` は生座標、`smoothed_distance` は中央値平滑化後の測定距離です。
- `moving_distance` は移動と判定された区間だけの平滑化距離です。
- 欠測を補間しません。累積距離の平らな部分は停止だけでなく未測定の場合もあります。
- 群の距離は有効な区間の合計です。全7個体の全経路の推定値ではありません。
- `distance_per_valid_fly_second` は群の距離÷有効な個体秒です。
  欠測が移動や接触に偏る場合、この補正だけでは偏りを除けません。
- 停止は中心の移動が小さい状態であり、毛づくろい・旋回・休息を区別しません。

`example_config.json` の初期設定：

| パラメータ | 初期値 | 意味 |
|---|---:|---|
| `threshold` | 30 | 背景との輝度差（0〜255） |
| `min_area_px`, `max_area_px` | 40, 500 | 検出成分の面積範囲（px²） |
| `collision_distance_px` | 28 | これより近い検出は不確実として除外 |
| `max_speed_px_s` | 1200 | この動画用の対応付け・距離計算の速度上限 |
| `assignment_margin_px` | 4 | 他候補との差がこれ未満なら対応を除外 |
| `smooth_window_s` | 0.1 | 中央値フィルタの時間幅。30fpsでは3フレーム |
| `speed_window_s` | 0.2 | 移動停止に使う後方時間窓の速度評価幅 |
| `move_start_speed` | 12 | 移動開始の速度閾値（px/s） |
| `stop_start_speed` | 6 | 停止開始の速度閾値（px/s） |
| `confirmation_s` | 0.15 | 閾値条件が続く最小確認時間 |
| `bin_s` | 1 | 時間集計幅（秒） |

速度閾値は設定では常にpx/sです。mm出力時は閾値も同じ倍率で換算するため、
単位変更だけでは移動停止の判定は変わりません。
状態が未確定の間はunknown。判定確定時は条件が続いた開始時刻まで遡ります。
短い閾値超えでは状態を切り替えません。欠測を挟むと判定をリセットします。
`moving_fraction_classified` の分母は移動＋停止の分類済み時間です。
unknownの時間は含めないので、分類済み時間も一緒に確認してください。

今回の動画には同じ画像が約3フレーム続く箇所があるため、フレームごとの瞬間速度を
そのまま移動停止判定に使うと誤判定します。`speed` は直近0.2秒の距離÷有効時間、
`instantaneous_speed` はフレーム間速度です。時間窓は欠測・区間変更をまたぎません。
この時間窓により移動開始・終了には遅れや時間的なぼけが生じます。

この閾値は実装の初期値であり、人手ラベルに対して検証済みではありません。
刺激（ファイル名の5〜10秒など）を自動的に実験条件として採用しません。
1秒集計から刺激前・中・後を実際の刺激時刻に従って比較してください。
複数容器の実験では容器・試行を実験単位として扱い、フレームを独立標本にしません。

## 前進・後退の判別（追加）

従来の図の灰色unknownは追跡または速度判定が不確実、青stoppedは中心移動が小さい状態です。
進行方向で分けた色ではありません。`activity.csv` の `activity_reason` で
`tracking_missing`、`segment_start_or_invalid_interval`、`speed_not_confirmed` を区別できます。

前進後退は別の軸で判定します。背景差分の各個体の画素から主成分分析で体の長軸を求めます。
しかし長軸には180度の曖昧さがあり、頭と尾を自動で確実に区別できません。
移動方向を頭の向きと仮定する処理は使いません。後退を前進と誤判定するためです。
この映像の解像度では形状だけの頭尾判別も未検証のため、頭側の確認入力を利用します。

1. `前進後退の頭側確認.command` をダブルクリックします。
2. 拡大画像の**頭側**をクリックします。水色の線は向き未確定の体軸、黄色の点は中心です。
   頭が分からなければNキーでスキップ。QキーまたはEscapeでそこまで保存して終了します。
3. 確認位置をCSVに保存し、前進後退の解析と `direction_report.png` の表示を行います。

現在の推奨結果は `results_retracked_px` です。旧処理の結果は `results_direction_px` に残っています。
頭側確認は追跡区間の開始、体軸の品質低下後、急な体軸変化後に求めます。
画像が不鮮明な場合は推測せずスキップしてください。確認済みの頭側から、体軸の
時間的連続性だけで頭向きを伝播します。欠測・区間変更・丸い輪郭・急な角度変化が
あると頭向きをリセットし、新しい確認を必要とします。
この伝播も正解姿勢に対して未検証で、緩やかな体軸誤推定による反転は残り得ます。

計算は、各フレーム間の移動ベクトルを両端の頭向きの平均に投影します。
直近の時間窓で「符号付き投影距離÷時間」を `longitudinal_speed` として求め、
「符号付き投影距離÷同じ頭向き有効区間の経路長」を `direction_cosine` とします。
方向解析用の移動状態で比率が+0.5以上ならforward（前進）、−0.5以下ならbackward（後退）、
その間ならlateral（体軸に対して横方向成分が大きい移動）です。
単一方向の直線移動では頭向きと移動方向の余弦に一致します。
停止状態はstopped、頭向き未確定・追跡不明・移動が小さすぎる場合はunknownです。
長い旋回など混合方向の運動もlateralに入り得るため、横歩きの確定ラベルではありません。

| 出力・列 | 内容 |
|---|---|
| `tracks.csv` の `axis_dx`, `axis_dy`, `axis_ratio` | 符号未確定の体軸と長短軸比 |
| `activity.csv` の `head_dx`, `head_dy`, `head_source` | 頭向きとその由来（手入力・伝播） |
| `locomotion_direction`, `direction_reason` | 前進・後退等のラベルと判定・不明の理由 |
| `longitudinal_speed`, `direction_cosine` | 体軸方向の符号付き速度と方向比率 |
| `direction_summary.csv` | スロットごとの前進・後退等の時間と測定距離 |
| `direction_report.png` | 灰色＝不明、青＝停止、緑＝前進、赤＝後退、紫＝横方向等 |
| `direction_preview.mp4` | 緑矢印＝頭向き、水色矢印＝直近の変位。方向ラベルを動画で確認 |

頭の向きが未入力でも停止判定は出力しますが、移動区間の前進後退はunknownになります。
`direction_summary.csv` のunknown時間には方向未確定の移動も欠測も含まれます。
その測定距離には有効に観測された区間の距離のみが入ります。
元の移動・停止図 `report.png` と、方向の図は別々に残します。

頭側CSVは `frame,slot,head_x_px,head_y_px` 形式です。
頭側の位置は、そのフレームの中心から見た長軸の頭側端点付近を指定します。
手入力済みなら以下で再解析できます（出力先は新規フォルダ）：

```sh

  --tracks fly_activity/results_retracked_px/tracks.csv \
  --config fly_activity/example_config.json \
  --head-anchors fly_activity/head_anchors_YYYYMMDD_HHMMSS.csv \
  --out fly_activity/direction_confirmed_new
```

自動体軸抽出には動画での新規実行が必要です。旧tracks.csvにも再解析できますが、
体軸列がなければ方向は不明になります。頭側確認ツールはOpenCVのGUI対応環境が必要です。
方向の追加閾値は `direction_min_axis_ratio=1.5`、`direction_max_axis_step_deg=40`、
`direction_min_cosine=0.5`、`direction_min_speed_px_s=3`。いずれも初期値です。

### 遅い前進の取りこぼしへの修正

旧実装では、方向判定を従来の移動判定（開始12px/s・確認0.15秒）で制限していました。
頭側へ進んでも、その速度・持続時間条件を満たさない場合は停止のままでした。
現在は方向解析用の移動判定を独立させ、初期値を開始6px/s・停止3px/s・確認0.1秒に
しています。`direction_move_start_speed_px_s`、`direction_stop_start_speed_px_s`、
`direction_confirmation_s` で変更できます。元の移動停止の `state` と `report.png` は
従来の閾値、方向解析の `direction_activity_state` と `direction_report.png` は新しい閾値です。
低い閾値には位置の揺れを移動と数える可能性があるため、停止区間の映像も確認してください。
頭側の符号は変更せず、速度閾値は前進・後退へ対称に適用します。

`頭側入力を再利用して方向再解析.command` をダブルクリックすると、この動画の最新の
頭側入力CSVを使って再解析できます。頭側の再クリックは不要です。
2026-10-13の最新入力 `head_anchors_20261013_150625.csv` による修正版の結果は
`direction_fixed_20261013_150625` です。7個体合計の前進時間は旧3.8個体秒から
新4.8個体秒になりました。これは閾値変更による集計差であり、正解ラベルに対する精度ではありません。

`direction_preview.mp4` の緑矢印は頭向き、水色矢印は直近0.2秒の始点から終点への
変位を正規化して表示します。旋回のある窓では、区間ごとの頭向きに投影した判定と
矢印の見た目が一致しない場合があります。CSVの `longitudinal_speed` が正なら頭側へ、
負なら尾側への移動成分です。確認動画には元の動画が必要で、座標CSV再解析時は
元結果のmetadata.jsonから動画を探すか、`--direction-video 元動画.mp4` で指定できます。

### 序盤の前進がunknownになる追跡不具合への修正

動画は30fpsですが、画像は約0.1秒ごとに更新され、中間の2枚はほぼ同じ画像です。
旧追跡は位置が更新されたフレームの移動を1/30秒として速度上限を適用し、
序盤の速い移動を異常ジャンプとして除外していました。その結果、表示スロットの
入れ替わりや細かい区間分割が生じ、距離・前進判定にも欠落がありました。

現在は画像間の輝度差から繰り返し画像を検出し、画像が更新された際の対応付け・速度推定・
ジャンプ除外に更新間隔を使います。繰り返し画像では位置予測を進めず、速度も減衰させません。
`tracks.csv` に `image_updated` と `measurement_dt_s` を保存し、再解析でも同じ判定を使います。
CSVの時刻や区間の経過時間を変更する処理ではありません。
この動画の例では速度上限も1200px/sへ調整しました。別動画では測定条件に合わせて設定します。

繰り返し判定の初期値は輝度差平均0.05以下かつ最大差8以下、更新間隔上限は0.2秒です。
`repeat_mean_difference`、`repeat_max_difference`、`max_measurement_dt_s` で変更できます。
非常に小さな実移動を繰り返し画像と判断する場合があるため、他動画への適用は確認が必要です。
0.2秒を超える更新間隔を無制限に対応付けへ利用することはありません。

最新の頭側入力95件を使った再追跡結果は `results_retracked_px` に保存しました。
新旧のスロット番号は一致しない場合があるため、頭側入力は同じフレームの検出中心が
2px以内で一意に一致する場合だけ移し替えます。`head_anchor_transfer.csv` に移し替えの記録、
`head_anchors_remapped.csv` に新しいスロット番号の頭側入力を保存しています。
新しい入力ツールは入力CSVの隣に `.csv.json` を作り、元の座標ファイルを記録します。
再解析ランチャーはこの記録を使って頭側入力を移し替えます。

今回、追跡区間は97から19、有効観測率は87.1%から91.9%になり、序盤の表示番号1では
最初の2秒の60フレーム中51フレームが前進になりました。検出率や正解一致率を意味する数値ではありません。
容器の縁の欠測・不鮮明な体軸・接触は引き続きunknownとして扱います。
旧データへの再解析だけでは座標の欠落を回復できないため、修正後の座標ファイルを使用してください。


## 停止個体のID保持と個体数の改善（2026-10-13）

- IDは動画内で予約し、移動中の再識別は15秒、静止IDは120秒を初期値とします。
  最大探索距離は240px。遠い位置への再対応付けは3枚の更新画像で確認します。
  GUIの保持時間と探索距離は撮影条件に応じて変更できます。
- 外見は面積・軸比・本体の平均輝度・輝度分散を緩やかに更新します。曖昧な候補や
  外見が大きく違う候補は割り当てません。期限後もID自体を他個体へ使い回しません。
- 自動個体数は、標本の30%以上かつ3フレーム以上で得られる上側の検出数と最頻値の
  大きい方を採用します。単発の過分割を除外し、接触が多い動画の過少推定を軽減します。
  これは成分数の推定であり、個体数を保証しません。指定数を超える検出が継続する場合は
  追跡品質画面で個体数・反射の確認を案内します。手動指定の個体数は自動変更しません。
- `tracks.csv` に `identity_state`、`identity_gap_s`、前回位置・再検出位置の差を保存します。
  `identity_events.csv` は再対応付けだけの一覧、`detections.csv` は割当前の検出一覧です。
  GUI「ID再対応付け」で行を選ぶと欠測前から確認動画を開きます。灰色の×は最後に
  観測した予約位置であり、現在位置の測定値ではありません。
